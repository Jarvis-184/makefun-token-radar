# Token Radar Board Schema

DISCLAIMER: All implied_value_usd figures are model-generated estimates, not real-time market prices. This data is for informational purposes only. No earnings or returns are promised, guaranteed, or claimed.

## Overview
The Token Radar `board.json` provides a ranked list of 200 crypto protocols based on estimated implied value. This file acts as the source of truth for the dashboard UI. It is generated by the core model and utilized by frontend components to render the board.

## Data Lifecycle
The `board.json` is automatically generated by the `scripts/audit-board.mjs` script after each successful model training run. The output MUST be validated against this schema before it is deployed to the production environment to ensure UI consistency.

## Data Structure
Each row in the board array represents a single protocol:

### Fields
1. `rank` (Integer): The position of the protocol (1-200). Must be unique and consecutive.
2. `slug` (String): URL-safe identifier (e.g., `protocol-name`). Must be unique and follow lower-kebab-case.
3. `name` (String): Human-readable protocol name (e.g., "Protocol Name").
4. `category` (String): Industry sector (e.g., "DeFi", "L1", "Bridge"). Used for UI filtering.
5. `implied_value_usd` (Float): Estimated protocol value in USD based on internal model metrics. Must be non-negative.
6. `confidence` (Float): Model confidence score (0.00 to 1.00). Reflects data quality and model certainty.
7. `farm_steps` (Array): Sequential strings detailing interaction steps for the protocol.
8. `notes` (String): Additional context, risk warnings, or unique protocol characteristics.

## Ordering Rule
The board MUST be sorted by `rank` in ascending order (1 at the top, 200 at the bottom). Any deviation results in an invalid board structure.

## Validation Checklist (20 Items)
1. `board.json` is a valid JSON array.
2. Array length equals exactly 200.
3. `rank` exists for every item.
4. `rank` is an integer.
5. `rank` range is 1-200.
6. `rank` values are unique.
7. `slug` exists for every item.
8. `slug` is URL-safe (lowercase, no spaces).
9. `name` exists for every item.
10. `category` exists for every item.
11. `implied_value_usd` is a number.
12. `implied_value_usd` >= 0.
13. `confidence` is a number.
14. `confidence` range is 0.0-1.0.
15. `farm_steps` is an array.
16. `farm_steps` contains at least one step.
17. `notes` is a string.
18. Entire board sorted by `rank`.
19. No duplicate slugs.
20. Schema version header is present.

## Common Mistakes and Fixes
1. `rank` is a string -> Cast to integer.
2. `rank` > 200 -> Review list length.
3. `slug` has uppercase -> Convert to lowercase.
4. `slug` has spaces -> Replace with hyphens.
5. `implied_value_usd` is negative -> Verify calculation.
6. `confidence` > 1.0 -> Cap at 1.0.
7. `farm_steps` is a string -> Convert to array.
8. Missing `notes` -> Provide empty string.
9. Duplicate `rank` -> Reorder rank.
10. Protocol missing -> Ensure exactly 200.
11. `category` misspelled -> Normalize to enum set.
12. Invalid JSON syntax -> Run linter.

## Versioning Policy
Use Semantic Versioning (Major.Minor.Patch).
- Major: Breaking schema changes (new required field, field removal).
- Minor: Adding new fields.
- Patch: Data updates only, schema remains identical.

## FAQ
- Q: Can I add new fields? A: Yes, but only in a Minor version update.
- Q: What if a protocol is delisted? A: Replace with another entry and maintain 200 count.
- Q: Where is the schema validated? A: In the `audit-board.mjs` script.
- Q: How often is the board updated? A: Daily by the automated pipeline.
- Q: What defines a category? A: Broad sectoral classification.
- Q: Are farm steps suggestions? A: Yes, they are not financial advice.
- Q: Is slug case sensitive? A: No, it is treated as case-insensitive in the UI.
- Q: Why limit to 200? A: UI performance constraints.
